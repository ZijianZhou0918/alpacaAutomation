# ADR-0001：采用模块化单体策略注册表

- 状态：已采用
- 日期：2026-07-17

## 背景

原实现以一个策略名同时驱动多项行为，实时服务还依赖进程全局可变策略上下文；WatchCode 入口存在单独硬编码，容易让观察池、买入和回测选择漂移。卖出和撤单虽有稳定保护，但无法独立替换。

## 决策

保留单进程模块化单体，增加四类结构化协议、独立命名空间注册表和命名 profile。配置先选择完整 profile，再允许四类独立覆盖；运行前一次性解析为不可变 `StrategyRuntime`。现有策略通过适配器接入，旧 `strategy_name` 和回测上下文保留兼容。

扩展只能由项目代码显式注册，不支持从环境变量动态导入任意模块。注册表在临时对象中完整构建后才发布为进程全局实例。

## 结果

优点：

- WatchCode、买入、卖出和撤单可以独立演进与组合。
- 非法配置在连接行情或券商前暴露。
- 实时调用不再依赖全局策略切换，并发和回测隔离更清晰。
- 原有策略文件、点击运行入口和默认业务行为继续可用。

代价：

- 新策略需要实现明确协议并在代码中注册。
- 策略配置在启动时固定，切换后需要重启对应进程。
- profile 的运行参数仍由 `Settings` 统一承载；未来若某分类需要专属复杂配置，应新增类型化配置，而不是自由字典或任意导入。

## 未选择方案

- 微服务：当前是单机交易进程，会增加部署、网络和一致性故障面。
- 全局可变策略名：无法安全支持一个进程内的独立组合。
- `.env` 模块路径或反射插件：扩大代码执行面，错误只能在运行深处暴露。
- 一次性重写所有策略：风险过高，无法用现有 200 多项交易回归证明兼容。
