# Alpaca MA5 项目运行手册

本项目可连接 Alpaca Live/Paper。每次检查、修改、测试或部署前，必须完整阅读本文件和根目录 `CODE_MODIFICATION_RULES.md`，再执行 `git status --short`。

## 1. 不可越过的边界

- 未获得用户对本次真实下单的明确授权，只允许源码检查、只读账户/日历/持仓/订单查询和 Fake/DryRun 测试。
- 不得运行 `tools/run_test_order.py`，不得启动可能自动下单的监控作为普通验证。
- 永远不要重启电脑。
- 不得输出 `.env`、API key、完整账户信息、通知 secret 或目标。
- 不得批量结束所有 Python、PowerShell、PyCharm 或浏览器进程。
- 不得未经核对删除 WatchCode、订单记录、排除记录、运行日志、状态文件或正式 SQLite。
- 美股交易日必须复用 `alpaca_ma5_service/trading_calendar.py`。
- 真实盘中买入窗口固定为交易日 `09:30 <= t < 12:00 ET`。

## 2. 每次任务的启动顺序

1. 完整阅读两份准则。
2. 运行 `git status --short`，区分用户改动、运行产物和本次文件。
3. 确认 `.env` 实际连接 Paper 还是 Live；只输出模式和非敏感阻断状态。
4. 检查项目生成器、监控、复盘网页、计划任务和本机重型任务。
5. 沿真实入口确认副作用，先做最小只读诊断。
6. 修改后按风险矩阵测试；只重启受影响的项目服务。

若任一准则缺失、不可完整读取或互相冲突，停止会改变状态的操作。

## 3. 当前运行链路

### 全天入口

`monitor_auto.py` 按交易所日历和 ET 时段进入：

1. 盘前：只读 Alpaca 当前持仓，滚动 60 秒涨跌达到 3% 时提醒；不生成或读取盘前 WatchCode；
2. 盘中：生成/读取 `watch_codes.txt`，运行 MA5 自动交易；
3. 盘后：生成/读取 `watch_code_afterhours.txt`，公开监控入口只提醒；
4. 休市或阶段结束：退出或生成报告，不得用工作日判断代替交易所日历。

### 盘中真实交易

```text
monitor_ma5_forever.py
  -> workflows/monitoring/intraday.py
  -> build_monitor_settings()
  -> resolve_strategy_runtime()
  -> service.run_forever()
  -> service.run_once()
```

`run_once()` 逐股执行买入、卖出、撤单的 check/execute/notify 阶段。真实写入集中在 `broker.py` 和 `order_guard.py`；策略组件只产生决策。

必须保持：

- WatchCode 候选只参与买入；卖出检查券商全部持仓；
- 四类策略在任何行情、账户或订单 I/O 前完整解析，未知名称失败关闭；
- BUY 使用策略最终买点的限价，不追价、不改市价；
- 开放订单、重复订单、每日名额、连续错误、止损和排除记录不能绕过；
- 订单提交后即使等待、撤单、账本或通知失败，也保留原 `order_id` 和暴露；
- 自动监控提交后不得在逐股循环同步等待终态；先原子写入 `outputs/pending_orders.json`，再启动提交通知并返回，后续每轮在读取持仓和产生新决策前按订单 ID 对账；
- 提交超时先按唯一 `client_order_id` 恢复；无法确认时暂停后续自动买入；
- 部分成交在剩余数量终态前仍是未确认暴露；
- 迟到成交使用券商累计成交量和实际成交均价幂等推进分档状态，终态状态只有在策略状态落盘后才能从待确认订单中删除；刚确认终态成交的股票在当轮继续按同向开放订单保护，避免持仓同步滞后造成重复买卖；
- `DONE_FOR_DAY`、`REPLACED` 不能直接当安全终态；
- 卖出前查询开放卖单，查询失败或已有卖单时不重复卖出。

行情口径也属于下单前硬风控：

- 每轮每股必须从同一 Alpaca feed 同时读取最近完成日线的 `RAW` 和 `SPLIT` 口径；日期缺失或价格倍数不一致时，视为公司行动切换，阻断该股盘前提醒、盘中买入、补仓、止盈和止损；
- Moomoo 与 Alpaca 实时价都必须提供可解析的行情时间，且属于当前市场日；自动交易用途在常规盘最多滞后 5 分钟、扩展时段最多滞后 30 分钟，明显晚于本机市场时间也必须拒绝；
- 盘前链路只能通过只读持仓接口确定股票范围，不得读取盘前 WatchCode、候选 CSV、Top 涨幅或全市场列表；无持仓时不得请求任何个股行情或发送提醒；
- 有持仓时使用 `premarket_observation` 行情用途，每 10 秒采样一次，只接受带行情时间的新盘前报价；按每只持仓滚动 60 秒窗口计算，当前价相对窗口低点上涨 3% 或相对窗口高点下跌 3% 才提醒，重复时间戳不得重复计算；提醒没有冷冻期，成功后从当前价建立新基线，同方向每累计新的 3% 继续提醒，反向达到 3% 独立提醒；发送失败不推进基线并在下一条新行情重试；实时行情源家族切换时先重建基线，不跨源计算波动；
- 当日 04:00 ET 后没有新盘前成交或报价时只显示等待，不得用日线收盘、旧缓存或无时间戳价格计算一分钟波动。`RAW/SPLIT` 公司行动切换继续安全阻断虚假波动提醒；
- 首选实时源失败、跨日或过期时可以切到 Alpaca，但备用价格也必须独立通过相同时间校验；所有来源失败时不得用日线收盘价、旧缓存或零值继续自动决策；
- 公司行动供应商可能在开盘前后更新复权状态，`RAW/SPLIT` 校验结果不得跨监控轮次缓存。

## 4. 当前启用策略

盘中入口启用 `ma5_dip_ladder` profile，复用 `ma5_dip` WatchCode 与首次买入信号；旧 `ma5_dip` profile 只保留为显式回滚/对照。权威参数位于 `alpaca_ma5_service/workflows/monitoring/intraday.py`：

- WatchCode：信号日 `close / MA5 >= 1.15`；
- 今日常规盘开盘价缺失时，首次买入失败关闭；
- 每只最多 `$2,500`、每日最多启动 3 只；首次 MA5 信号时的当前价是固定买入锚点；
- 买入预算按锚点、`-1%`、`-2%` 各三分之一，以整数股 BUY LIMIT 串行执行；触及第二档后若未买满又回到锚点，首档价补足剩余预算；
- 三档买满或到 12:00 ET 后继续持有；相对全部实际成交的券商加权平均成本达到 `+10%` 时，才建立止盈锚点，并仅将首次 `50%` 半仓止盈额度按锚点、`+1%`、`+2%` 拆成三档；
- 半仓止盈额度的前两小档已卖而第三小档未成，价格回到止盈锚点时只 MARKET 卖掉这笔半仓额度的剩余数量，不得清掉另外 `50%`；
- 相对全部实际成交的券商加权平均成本达到 `-10%` 时 MARKET 全部止损；未卖仓位在 15:55–16:00 ET MARKET 清仓；
- 每次本功能启用后的买入成交必须把计划标记为需要券商保护，并立即按 Alpaca 最新持仓数量和加权平均成本提交全仓 `-8%`、`GTC`、`STOP MARKET`；补仓或部分卖出后通过 Alpaca replace 更新数量和触发价，进程重启后按 `ma5-stop-*` 客户端订单号收编已有保护单，不重复提交；
- 主动止盈、软件止损或尾盘清仓前必须先撤销同股保护单，并只在券商确认零成交终态后提交新卖单；保护单部分成交、撤单待确认或结果未知时禁止第二张卖单，保护单成交后立即请求撤销同股托管买单并把计划转为 stopped；
- 自动订单提交后立即返回逐股循环；普通订单 600 秒仍未终态时由持久化监督器请求撤单，不阻塞其他股票的止损或尾盘清仓；`broker_protective_stop` 不适用 600 秒超时，直到被触发、被主动退出链确认撤销或由持仓对账处理；
- 固定限价在 `$1` 以下保留四位小数，`$1` 及以上保留两位小数。

计划状态写入 `outputs/ladder_state.json`，未终态订单和策略动作写入 `outputs/pending_orders.json`，均采用临时文件加原子替换；每档部分成交按订单累计成交量幂等应用，迟到成交不会重复补买或重复卖出。刚成交后允许 120 秒券商持仓同步宽限；刚确认终态成交的股票当轮仍按同向开放订单保护，下一轮重新读取持仓后才继续买卖。超过宽限仍无持仓才结束活动计划。状态文件无法解析时必须在账户/订单 I/O 前停止；同股开放买单未知或未终态时暂停卖出，避免买卖竞态。历史已关闭计划允许同一股票在后续交易日建立新计划。不得手工删除活动计划或待确认订单来绕过开放订单、对账或止损。

Alpaca `STOP MARKET` 的 `-8%` 仅是触发价，不保证最终成交价；跳空、停牌、快速行情和流动性不足仍会产生滑点。该保护单只在常规交易时段触发，不替代盘后风险管理；本项目仍保留 `-10%` 软件 MARKET 止损和 15:55 ET 清仓。上线前必须用 Fake/DryRun 覆盖创建、替换、重启收编、部分成交和撤单竞态；未经用户明确授权不得用 Paper/Live 订单做验证。

任何可影响交易结果的默认值变化，都要单独说明、覆盖边界测试，并且不得自动启动 Live 监控。

## 5. WatchCode

- `data/watchcodes/watch_codes.txt`：盘中自动交易观察池；
- `data/watchcodes/watch_codes_premarket.txt`：历史遗留文件；当前盘前链路完全忽略且不再生成；
- `data/watchcodes/watch_code_afterhours.txt`：盘后观察池。

文件顶部 `signal_date` 必须对应最近一个已完成日线的交易日。盘中池还必须包含由当前 `ma5_dip` 选股参数规范化生成的 `# Rules:`；启动监控前同时核对日期和规则，任一不符都重新生成。`monitor_auto.py` 和直接 `monitor_ma5_forever.py` 入口都执行这项检查并失败关闭。已有盘前/盘中生成器时等待其完成，不能重复启动。网页、PyCharm、命令行和计划任务都可能是任务来源。

WatchCode 是运行产物。除非用户明确要求，不得回滚、清空或用旧文件覆盖。

## 6. 复盘网页

- 入口：`open_daily_review.py` / `open_daily_review.cmd`
- 默认起始端口：`127.0.0.1:8788`
- 健康检查：`GET /api/review/health`
- 任务状态：`GET /api/actions/status`
- 生命周期：仅由双击入口或 QuickTools 首次复盘请求启动；连续 10 分钟没有 HTTP 请求后自动关闭监听，下一次请求会重新静默启动。

用户选择哪一天就只展示哪一天；休市、停牌或无交易可以为空，不得回退日期。净资金流水不是收益，必须区分已实现盈亏、未实现盈亏、费用、现金流和权益变化。券商与本地账本不一致时优先保留“手动交易”解释，不自动改账。

POST 动作必须限制在回环地址、白名单、空请求体、同源和 `X-MA5-Action: 1`。停止监控只停止本项目进程，不自动撤销券商订单。

## 7. 通知

项目统一调用 `alpaca_ma5_service.openclaw_notify.safe_send_notification()`。买卖订单通知使用固定字段纯文本/Markdown：首行必须直接显示“买单/卖单 + 中文状态”，随后依次显示股票、账户、原始状态、方向、数量、价格、估算金额、订单号、策略原因、执行结果和下一步；Live 必须明确标为“真实账户”。`ACCEPTED/SUBMITTED`、部分成交、状态未知、撤单中、撤单完成、拒单和 `DRY_RUN` 必须分别表述，不能把“已提交”或模拟结果写成“已成交”。通知失败不得改变交易结果或中断主循环；通知成功也不代表订单成功。未经授权不得发送真实测试消息或修改外部通知项目。

## 8. 进程与计划任务

结束进程前必须读取 `Win32_Process.CommandLine`，同时匹配本项目绝对路径和具体入口。陈旧 PID、runtime 文件或历史任务结果不能单独证明进程仍在运行。

仓库只保留一个 Windows 自动化任务：`AlpacaMA5-0050-GenerateWatchcodes`。它按本机时间每天 00:50 调用 `tools/run_daily_watchcodes.ps1`，只运行 `watchcode_ma5.py` 生成盘中观察池及候选报告；不得运行盘前选股。任务不启动监控、不读取持仓、不提交订单，使用动态仓库路径、当前用户交互登录身份、`StartWhenAvailable` 和 `IgnoreNew`，运行日志写入 `outputs/logs/watchcode_daily_YYYYMMDD.log`；电脑关机或用户未登录时不能准点运行，条件恢复后由 Task Scheduler 补跑。

安装入口为 `tools/install_daily_watchcode_task.ps1`。安装后必须只读核对任务动作、参数、每日 00:50 触发器和下一次运行时间；验证时不得立即运行任务或生成 WatchCode。`monitor_auto.py`、`monitor_ma5_forever.py` 和其他 WatchCode 入口仍只能由用户通过命令行或复盘网页明确启动。

如果机器上发现历史遗留的 `AlpacaMA5-*` 任务，必须先核对任务动作和归属；不能因为仓库已删除启动脚本就把历史任务视为安全或仍然有效。

未经用户授权不得创建、删除、启停或立即运行计划任务。不要为了验证任务返回码而手动运行 00:50 任务。

## 9. 正式日线 SQLite

正式路径：`backtest/data/market_data.sqlite`。

- 来源固定 Alpaca SIP、`1Day`、`split`；
- 正式库只保留日线，`minute_bars` 必须为 0；
- 股票池包含可识别的 active/inactive 普通股，但不能宣称完全消除幸存者偏差；
- 新的日线研究只能优先只读此库，覆盖不足必须报告；
- 分钟行情不得写入正式库。

唯一保留的数据维护入口：

```powershell
.\.venv\Scripts\python.exe run_backtest_daily_history_rebuild.py `
  --start-date 2024-07-17 --end-date 2026-07-16
```

它先写 staging，校验元数据、OHLC、覆盖、空分钟表和 `PRAGMA quick_check`，再备份并原子替换正式库。重建属于重型任务，必须全局串行；它不读取持仓/订单、不下单、不启动监控。

`backtest/reporting/` 仅保留为通用历史报告组件。经明确授权的 `run_backtest_kdj_volume_reversal.py` 是独立只读研究入口：只读正式 SIP/split 日线库，收盘确认量价与 KDJ(81,3,3) J 信号，下一交易日开盘成交；样本末未退出仓位按末日收盘估值。它不连接账户、不下单、不生成 WatchCode、不接入监控。其他旧策略、旧优化器、旧分钟缓存或旧报告不再保留。

### 通用

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe -m pytest -q
git diff --check
```

### 按风险补充

- 策略/订单：目标测试 + 全量测试；Fake broker 断言零真实提交；
- 日历/时间：交易日、周末、节假日、半日市和窗口边界；
- WatchCode：信号日、目标文件、空候选、过期、并发和原子写；
- 复盘/Web：精确日期、空日、GET/POST/404/405、同源、路径穿越和进程归属；
- SQLite：临时数据库、schema、只读、覆盖、幂等和 quick check；
- PowerShell：AST 解析；未经授权不注册或运行任务；
- 通知：patch 外发，验证异常不影响交易。
- 行情安全：覆盖 `RAW/SPLIT` 一致、拆股切换、跨交易日、盘前 04:00 会话边界、盘中/扩展时段过期、用途隔离和备用源；Fake broker 断言异常时买卖均为零；

修改运行逻辑后，重启并检查受影响服务。监控修改只能先做 Fake/DryRun；启动真实监控仍需明确授权。验证报告必须明确是否提交过订单，默认答案为“没有”。
